# Difference between a fault and a failure
* Fault = a bug or mistake in the code (hidden problem).
* Failure = what goes wrong when the program runs because of that bug (visible problem).
  
`if (age > 18) instead of if (age >= 18)`

➜ This mistake is the fault.

➜ The incorrect behavior is the failure when 18-year-old user gets rejected.

# Main software testing challenges
* Test coverage – You can’t test everything, so testers must focus on the most important and risky parts.
* Time & effort – Testing takes time, people, and money, and deadlines are often tight.
* Choosing the right tests – There are many testing methods, and picking the right one isn’t always obvious.
* Test environment – Creating a test setup that matches the real production system can be difficult and expensive.
* Finding root causes – When something fails, figuring out why it failed can take a long time.
* Interoperability – Testing how different systems work together can become complex very quickly.
* Scalability & performance – Some problems only appear when the system is under heavy load or many users.

# Software Testing Types – Quick Summary

- **Functional testing**  
  Verifies that the software functions work as expected.

- **Non-functional testing**  
  Evaluates quality attributes such as performance, security, and reliability.

- **Structure-based testing**  
  Uses internal code structure and coverage (e.g., statements, branches) to design tests.

- **Behavioral testing**  
  Tests system behavior using workflows, models, and user interactions.

- **Capacity testing**  
  Checks how the system performs under different load levels.

- **Usability testing**  
  Evaluates how easy and user-friendly the software is for end users.

- **Acceptance testing**  
  Confirms the software meets business requirements and user expectations.

- **Regression testing**  
  Re-tests existing functionality after changes to ensure nothing is broken.

- **Alpha and beta testing**  
  Testing by limited users before full public release.

- **Localization testing**  
  Verifies software behavior across different languages and regional settings.

- **Compliance testing**  
  Ensures the software follows required standards and regulations.

- **Risk-based testing**  
  Prioritizes testing based on risk and business criticality.

- **Accessibility testing**  
  Ensures usability for people with disabilities.

- **Configuration testing**  
  Tests the software across different environments, devices, and configurations.

- **Upgradation testing**  
  Validates software upgrades and migrations work correctly.
  
- **Fault-based testing**
  Designs tests based on known or expected fault types & Helps target specific classes of defects

- **Model-based testing**
  Uses models of system behavior to generate test cases and expected results
  
- **Static testing**
  Reviews, inspections, and analysis without running code

- **Dynamic testing**
   Executing the software to observe behavior

# Common techniques include:
* Boundary Value Analysis
* Equivalence Partitioning
* Decision Tables
* Use Case Testing

Effective testing techniques require clear methods, defined scope, clear goals, and the right balance between manual, automated, functional, and structural approaches.
